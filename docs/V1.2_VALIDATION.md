# Global News Monitor v1.2 local validation

The development branch starts at the published v1.1.0 tag, commit `5d3ab1f`.
This report covers an isolated Windows rehearsal on November 24, 2026.
The baseline and candidate both used PostgreSQL 17.11 with PostGIS 3.7.0
and the same copied data. The production site and Azure resources stayed in
place throughout the work. [Published release](https://github.com/fegalvan/Global-News-Monitor/releases/tag/v1.1.0)

The follow-up [news relevance audit](NEWS_RELEVANCE_AUDIT.md) reviews the
publisher links, checks upstream fields, and measures how relevance issues
affect the candidate's results.

## What the dashboard measures

| Measure | v1.2 decision |
| --- | --- |
| Record totals, locations, country ranks, category mix | Kept the existing counts. The dashboard now labels the counts as GDELT records and explains map cell density and the source of location detail. |
| Hourly or daily chart and seven-day average | Kept completed-update rules. The UI explains gaps and preserves complete periods with zero records. |
| 24-hour and seven-day comparisons | Kept equal UTC periods, withheld percent changes below a baseline of 20, and added category differences for complete comparisons across all categories. |
| Unusual increases | Kept the v1.1 matched weekly median and robust scale. The main card shows sample availability, the typical count, and the current count. The score and thresholds remain available in the explanation. |
| Original spike and Goldstein actor-pair summaries | Kept the legacy routes and CLI. The dashboard uses the baseline above for unusual increases. Goldstein is an event-type weight and remains unsuitable as a general tension gauge. |
| Legacy CLI momentum | Corrected the 24-hour count to an hourly rate by dividing by 24. The command still describes observed, overlapping windows. |
| Source coverage | Groups trimmed exact URLs across up to 20,000 recent matching records. Source counts refer to distinct links in those records. The API returns the latest 12 links, and the dashboard exposes the eight leading domains as filters. |

The coverage panel uses publisher domains and GDELT classifications because
the Events export provides references rather than article titles or summaries.
Its timing is the GNM record time, which normally comes from GDELT's
`DATEADDED`. Source links offer context for a comparison. URL variants and
syndicated stories can still appear separately. [Coverage method](TECHNICAL_WALKTHROUGH.md#finding-the-news-coverage-behind-a-change)

## Real data and automated checks

The preview copy contained 251,158 real event records and 234 completed
source slots from November 22 at 17:00 UTC through November 25 at 03:15 UTC.
The fixed comparison ended November 25 at 03:00 UTC. Both 24-hour periods
had all 96 expected exports. Direct counts of normalized records were
114,228 current and 108,817 previous, an increase of 5,411 records or 4.97%.
The seven category differences matched direct SQL and summed to 5,411.
Diplomacy accounted for the largest signed change, at +2,892 records. The
seven-day comparison and spike indicator withheld their results because the
copy had too little history.

An independent pass over the newest 20,001 joined rows confirmed the coverage
cap, link grouping, and recency order. The API inspected 20,000 of the 114,228
records in the selected 24 hours. Those 20,000 records linked to 3,836 distinct
stored URLs. Sample article domains, newest matching categories, timestamps,
and record counts agreed with the database. A single HTTPS metadata request
to one stored link each at NBC News, The Guardian, and BBC returned HTTP 200.
Publisher access can vary by site.

The official GDELT export for November 25 at 02:45 UTC was also ingested into
a fresh disposable database. All 807 rows were inserted. Raw identities,
normalized rows, and summed hourly records were each 807, with one complete
source slot. Replaying the same file inserted zero rows. Synthetic fixtures lived
in separate test databases and covered outcomes that need longer history,
including missing exports, complete zero counts, an elevated anomaly,
downgrade, recovery after a failed migration, retries, and deduplication.

- **93 Python tests passed**, including PostgreSQL and Alembic integration tests. Starlette TestClient and Alembic emitted their existing dependency/configuration deprecation warnings.
- **9 frontend tests passed**, along with TypeScript and the production Vite build.
- Chromium 158 passed world map zoom, reset, and country selection, comparison drill-downs, country and source filtering, event pagination, filter reloads, manual refresh, and empty states. A delayed request tested the loading message, and a simulated API failure tested recovery. Layout checks covered 320, 390, 680, 900, and 1,440 px widths. I also reviewed the rendered desktop and mobile captures.
- `npm audit` reported zero advisories and `pip check` reported no broken requirements. `pip-audit` reported six distinct advisories against the pre-existing local `pip` 25.0.1 packaging tool. It reported no other installed packages. The source scan matched no private key or GitHub token patterns.
- The preview role ran read-only and had no privilege to insert normalized rows. Publisher links open separately with no opener or referrer. The API reads the stored references using parameters and leaves requests for publishers to the browser.
- A new Trivy Linux image scan was unavailable on the local host. The [v1.1 candidate scan](V1.1_VALIDATION.md#candidate-security-gate) remains historical evidence, including its unresolved upstream findings.

## Same-machine benchmarks

Each number is a median in milliseconds over 12 successful loopback
requests after one warm-up. The v1.1 baseline came from the tagged code.
The two API processes read the same cluster and filters, and timings were
alternated on existing routes. The seven-day selections used the available
two-plus days of GDELT data. They establish behavior with a partial window.

| Request | v1.1 median | v1.2 median | v1.2 max |
| --- | ---: | ---: | ---: |
| Global analytics, 24 hours | 49.9 | 49.5 | 52.7 |
| Global analytics, seven days | 56.0 | 55.3 | 85.9 |
| World map, 24 hours | 129.0 | 129.8 | 133.5 |
| First page of event records | 42.3 | 41.7 | 44.8 |
| Global trends | 49.8 | 53.9 | 57.7 |
| United States profile, 24 hours | 894.5 | 156.7 | 169.3 |
| Global coverage, 24 hours | — | 263.1 | 266.9 |
| Global coverage, seven days | — | 261.5 | 265.4 |
| United States politics coverage | — | 84.0 | 86.5 |
| Global coverage for the leading domain | — | 260.0 | 265.9 |

The v1.2 dashboard's country profile requests location counts. The older
request also parses source URLs for all matching records. Both request
shapes remain available. The difference reflects moving the profile's source
exploration to the bounded coverage lookup. The global coverage response
was 3.9 KB before compression. `EXPLAIN ANALYZE` used `idx_events_time`,
completed in 268 ms, and wrote zero temporary blocks for that request.
These are local API measurements with a warm
database cache. Azure compute, network timing, concurrent traffic, and a full
17-day collection window can produce different results.

## Resource implications

The existing 17-day detail and 90-day hourly retention work as before.
The link lookup uses the current tables and time indexes. The release has
no database migration, new dependency, additional feed, or paid service.
The most recent project estimate remains about $3.65 per month within the
existing $5 budget and spending limit. The new endpoint adds query work when
a visitor opens coverage, and the full 17-day Azure load needs its own
measurement. [v1.1 Azure resource measurements](V1.1_VALIDATION.md#three-hour-production-follow-up)

## Local review

The Windows review preview serves the fixed 24-hour comparison from a
separate copy of the v1.1 local database. Vite, FastAPI, and PostgreSQL listen
only on loopback. The scheduler is stopped so the sample stays fixed, and
the update indicator will age normally. The v1.1 services were shut down
before copying the data. The original database, backups, screenshots, and
verification artifacts are still available. The GitHub Desktop stash was
inspected and preserved. [Local setup](LOCAL_DEVELOPMENT.md)
