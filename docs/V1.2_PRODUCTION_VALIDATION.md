The scheduler paused at 15:32:21 UTC. The final protected backup was
31,999,280 bytes. Revision `0012_category_quality` took 39 seconds from the
operator’s migration command. It updated 5,644 category assignments or rule
details. All 284,860 raw and normalized identities and both hourly totals
matched before and after. The raw fingerprint, archived contributions, and
246 covered slots also matched. The last pre-switch export was 15:30 UTC.
There were no aggregate-only hours, so the actual category history cutoff
was null. The new API tables were readable by the API role. The API could
still not write event records, and the ingestion role could neither write
the revision table nor create objects in the public schema.

The API and web were checked before resuming the scheduler at 15:34:26 UTC.
The three running IDs matched the scans. The previous v1.1 image tags,
configuration, and protected backup were kept. The VM, managed database,
retention settings, and expected $3.65 monthly footprint stayed in place.

Context recovery ran separately with the scheduler active. The first
12-file production dry run matched 7,078 of 7,078 eligible records.
The apply passes were capped at 24 exports per batch and completed from
15:37:06 to 15:38:34 UTC. All 284,860 eligible records matched across 246
files. No files were unavailable, no records were left unmatched, and
no coordinates needed clearing. GDELT supplied a country value for 160,352
first actors and 126,027 second actors. Blank values remain unknown.
The context table occupied 19.58 MiB with its index. The temporary
category undo information occupied 0.71 MiB and follows raw retention.

The initial images ran from `56f57a1`. Production query plans exposed a
full raw-table scan in worldwide coverage. A new image confined raw URL
lookups to the inspected records. The first attempt to switch to that
build failed liveness because the staged Python module was readable only
by root. The recovery procedure restored the healthy initial v1.2 images.
The build staging permissions were corrected and checked as the runtime user. The
newly scanned images went live at 15:46:39 UTC. No database migration or
category changes were needed for the second switch.

## Release notes

- Follow a country, map selection, or matched-period change into original
  GDELT links. Browse by varied sources or by most recent and see the
  coded action, location precision, and underlying record.
- Compare equally covered periods and see which categories contributed to
  the change. The anomaly indicator needs enough comparable weeks.
- More specific Cyber and Crisis rules and corrected CAMEO labels reduce
  misleading category assignments. The held-out checks also found missed
  relevant stories. Original GDELT records and known upstream mistakes
  remain visible. [News relevance audit](NEWS_RELEVANCE_AUDIT.md)
- The parser keeps geographic precision and actor-country fields, and verified
  original exports supplied context for retained records.
- The production query plan helped reduce worldwide link lookup time while
  preserving the coverage groupings and both display orders.
